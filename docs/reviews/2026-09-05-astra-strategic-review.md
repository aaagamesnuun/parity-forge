## 優先所見

### 1. 公平性の対象を先に固定する

[憲章](../CHARTER.md)は複数の強さでの公平性を求める。しかし次の三つは異なる。

| 対象 | 問うこと | 測定の単位 |
| --- | --- | --- |
| 完全プレイ | 最適に指すとどちらが勝つか、引分か | 固定された単局の初期状態 |
| 有限技能での体験 | 対象とする実力の両者に勝機と判断の余地があるか | 役割・先後・強さを固定した対局群 |
| 交代マッチ | 役割や先後を交代した総得点が釣り合うか | 交代方法まで定義した複数局 |

有限・決定的・完全情報の固定初期状態では、完全プレイの値は A勝・B勝・引分の
いずれかになる。完全プレイで引分以外の「勝率50%」を期待することはできない。

旧 [cascade.py](../../src/parity_forge/cascade.py) は exact の強制勝ちを却下する。
一方、Plan 0013 の [atlas_protocol.py](../../src/parity_forge/atlas_protocol.py) では
自然引分を認めず、exact DRAW は手数上限のみである。別々の研究の条件を合わせて
「強制勝ちは不可、自然引分なし、上限引分も不可」を要求すると、単局の完全プレイ
公平性に通過対象はない。憲章がこの全条件を同時に要求すると断定するものではなく、
次研究で解くべき目的の曖昧さである。

**提案:** 主目的には「対象とする有限技能での単局の公平性」を置き、完全解の値と
交代マッチの成績を別欄にする。強制勝ちの存在は明示し、その勝ちが一手で見えるのか、
十分な読みを必要とするのかも区別する。これは目的の選択なので、ユーザーが完全プレイの
非敗北対称性を重視する場合は、自然引分を含む別の設計が必要になる。

### 2. 先後合算の五分を発見の主ゲートにしない

Plan 0013 の exact frontier は `FIRST_PLAYER_DOMINANT` または
`SECOND_PLAYER_DOMINANT` を通す設計である。既存の14組は depth 1 の各128対局で
先手が全勝し、A-first の64局をA、B-first の64局をBが勝ったため A/B=64/64 になる。
参照: [protocol](../../src/parity_forge/atlas_protocol.py)、
[depth-1 の判断記録](../DECISIONS.md)。

単独ゲームの公平性とは呼ばない契約も存在するため、隠れた集計バグではない。
ただし、この routing signal を増やすことと良い単独ゲームの発見の間には距離がある。

**提案:** 次研究の主表を `役割 × 先後 × agent構成 × 強さ` にする。異なる先手条件を
平均して偏りを隠さない。実際に提供する単局の先手ルールと評価対象を一致させる。

random と terminal-only depth 1 は局所的な基準として有用だが、後者の非終局葉は
すべて0であり、戦略的な強さの校正には不足する。同じ深さ・同じ実装を両役割に
与えることも、同じ実力の保証にはならない。深さや予算を増やしたときの偏りと、
片側だけ強くしたときの変化を観察する必要がある。各ゲームで必ず単調に勝率が上がると
仮定せず、評価器の限界として記録する。参照: [EVALUATION](../EVALUATION.md)。

### 3. 完全な会計と全クラスの成立を分ける

Plan 0015 の負結果は妥当である。109クラス中9クラスの静的供給が0なら、履歴除外を
行っても増えず、各クラスに5件以上を求める条件は満たせない。census `COMPLETED` と
partition `NOT_STARTED` の区別も正しい。

一方、良いゲームの発見に、すべての構文上のクラスが成立することは必要ない。
既存報告には880,986件の静的適格代表があり、残り100クラスのゲーム品質は未測定である。
参照: [負結果報告](../../experiments/reports/0015-static-breadth-floor-negative.md)。

最新の Plan 0016 草案は、全109クラスに同じ条件を適用して全採否を記録する設計に
変えている。この修正は妥当であり、100クラスの手動救済とも、Plan 0015 の成功への
読み替えとも区別されている。

残る懸念は割当の規模である。草案は支持される各層に開発2件・reserve2件を割り当てる。
履歴除外前の2,251層を上限にすると、開発だけで4,502 carrier になり得る。
これは直ちに全件の gameplay を実行する計画ではないが、その大きさが次の研究の問いに
必要か、先に決める価値がある。**公平性の定義・評価器校正・最初の評価予算を明確にして
から、必要な割当範囲を凍結する**ことを勧める。

普遍的な成功条件は、実装前に小さな不可能性の証明で点検すべきである。例えば両役割が
CONVERT/ELIMINATE の場合、両者の初期駒数が正なら、合法な変換による駒数は

```text
(a, b) → 先手の変換 → (a+1, b-1) → 後手の変換 → (a, b)
```

と推移する。後手は先手の駒数を0にできない。途中でゲームが終了しても、その後の
到達可能性は生まれない。「双方の ELIMINATE 到達可能性」という静的必要条件の不成立は、
盤面を全列挙せず計数規則から分かる。参照:
[initial_structure.py](../../src/parity_forge_universe/initial_structure.py) の
`_next_count_states`、`_goal_count_satisfied`、`_make_table_row`。
これは9クラスすべての原因説明ではなく、全109成立を早く反証できた一例である。
完全な分布地図を得た census 自体の価値まで否定するものではない。

### 4. 探索の試行錯誤と確認実験で運用を分ける

物理行数集計では `src` は67ファイル・91,118行、`tests` は79ファイル・54,153行。
主要な DSL、engine、solver、agents、terminal_search、play、symmetry、generator、
analysis、asymmetry、simplicity の11ファイルは計3,403行だった。名前に evidence /
experiments / protocol / stage を含む21ファイルだけで36,508行ある。粗い分類であり、
残り全部が無駄という意味ではないが、新実験の周辺実装を増やす費用は大きい。

全テストには過去の1,025件の checkpoint で約82分を要している。それでも旧769件の
テストは、本番 telemetry join の tuple/list と終端 zero-legal observation の統合不具合を
捕捉しなかった。修正は Plan 0014 の実データ境界テストで行われた。参照:
[過去の technical debt](../BACKLOG_HISTORY.md)、
[assessment repair tests](../../tests/test_atlas_assessment_repair.py)。

**提案:** 次研究から、探索用は版・seed・設定・失敗を残す小さな反復可能 runner にし、
条件を変えた試行を別IDで記録する。確認用は独立集合と凍結した判定を使用する。
探索で結果を見て改善した事実を明記すれば、その探索を新鮮な確認証拠と呼ぶ必要はない。
既存の one-shot 契約と結果は維持し、新しい区分を別途登録する。

新規向けの証跡共通化は、次の具体的な runner に必要な範囲に絞る。大規模な共通
framework の開発を先行させない。テストは本番と同じデータ形状で manifest → execution →
ledger → telemetry → assessment を通る少数の縦通しを優先する。現在のコード変更完了前の
全テスト要件は維持し、開発用の速い境界テストと併用する。

## 勧める次の一研究サイクル

以下の件数は規模感の提案であり、凍結済みの割当・成功閾値ではない。

1. **現在の closeout。** 既存の全回帰テスト結果を確認して Plan 0015 を閉じる。
   負結果と未実施 partition を残す。新 primitive 追加を既定の次手にしない。
2. **一頁の目的定義と小さな評価器校正。** 単局公平性の対象技能、先手条件、引分の
   扱いを定義する。候補ブロックと離れた8件程度の合成例で、先手全勝、役割全勝、
   一本道、意味のない分岐、上限循環、読みの深さで変化する形を点検する。
   期待分類を先に書く。既存 fixture の再利用は既知の校正資料と明記する。
3. **一般規則による小規模な開発集合。** 校正後の独立計画で最大24 carrier 程度を
   提案する。support・除外・構造層の配分・順位・上限・打切りを選択前に固定する。
   全109クラスの供給会計と24件の評価対象を区別し、未評価クラスへ品質を一般化しない。
   Plan 0016 草案の全層割当を採用する場合も、最初の評価集合とその決め方を先に考える。
4. **強さへの反応と、人が理解できる診断。** random / depth 1 と事前固定した追加の
   深さ・予算を比較し、片側を強くする対戦も測る。exact 値、短い強制勝ち、各役割の
   選択肢、打切りを別々に報告する。共通 seed・向きの測定を独立標本と仮定しない。
   合格・不合格を含む少数例を DSL 由来のルールと局面で説明できる形にする。
5. **小さな人間校正を早める。** 研究者本人による理解しやすさ、両役割で考える余地、
   再戦したいかの比較を、発見候補の正式確認と分離して行う。未実施なら未校正と記す。
   外部参加者の募集や公開は別の許可事項である。

terminal-blind probe は「観測後にどの判断を変えられるのか」を説明できる場合に採用する。
出力を後続の選択・評価・予算設計に使わないなら、さらに独立した基盤フェーズを挟む価値を
点検する。直接の小規模 gameplay との比較も次計画の設計で行う。

停止条件は事前に固定する。整合性不一致なら選択前に止め、予算超過は unknown/censored、
固定集合に候補がなければその集合での負結果とする。出るまで追加採集することを同じ
確認実験に混ぜない。新 primitive は具体的な不足行動と比較可能な仮説が示された場合に検討する。
