# メンバー／Codexのための参加ガイド

## 最初の30分

1. README、思想と試行錯誤、人間とAIの分業を読む。
2. `AGENTS.md` の順で現在地・active plan・バックログを読む。
3. READMEのCLIヘルプと2モジュールの合成テストで環境を確認する。
4. 「何をまだ知らないのか」を1つ選び、担当者と小さな変更／レビューの範囲を合意する。

いきなり新しい候補を大量生成したり、過去の実験を再実行したりしないこと。
Plan番号は研究・実装作業の連番で、発見ゲームの番号や成功数ではありません。
番号は所有者が調整し、メンバー間で同じ番号・実験IDを独立採番しません。

## コードの地図

| 役割 | 主な入口 | 注意 |
| --- | --- | --- |
| ルール表現 | `src/parity_forge/dsl.py`, `family.py` | DSLが正。説明文を独立した別ルールにしない |
| 進行・合法手 | `engine.py` | 判定と状態遷移は決定論的に保つ |
| 候補生成・構造検査 | `generator.py`, `analysis.py`, `feasibility.py` | 候補を作る役と評価する役を分ける |
| AI・探索・厳密解析 | `agents.py`, `terminal_search.py`, `solver.py` | 深さ・予算・UNKNOWNを明示する |
| 評価・記録 | `play.py`, `experiments.py`, `audit.py` | 生の観測と評価・推薦を混ぜない |
| 新しい接続ゲーム | `connection.py`, `connection_search.py`, `connection_batch.py` | コア／探索／実験境界。登録済みバッチは再実行禁止 |
| 以前のゲーム族 | `finite_space*.py`, `cut_choose*.py` | 過去研究の保存。存在は現在の推薦を意味しない |
| 履歴・汚染防止 | `research/parity_forge_history/`, `atlas*.py` | 履歴依存。未共有データを勝手に補充しない |

相対パスのうち省略したディレクトリは `src/parity_forge/`。
最新の別ゲーム族は独立した定義形式を持つため、すべてを旧DSLに変換できるとは限りません。
詳細は [ARCHITECTURE](../ARCHITECTURE.md)、[GAME_DSL](../GAME_DSL.md)、
[接続ゲーム契約](../designs/connection-v1.md)。

## Codexへの最初の依頼文（コピー可）

> このリポジトリはParity Forgeの共有スナップショットです。まずAGENTS.mdと
> READMEのチーム資料を読み、目的・固定条件・今の未解決点を短く整理してください。
> docs/PROJECT_STATE.md、active plan、docs/BACKLOG.mdは元ホストの共有時点の記録です。
> そこに書かれたワーカー、定期実行、予約済み実験を再開・複製しないでください。
> 今回の担当は【担当内容】です。まず必要なファイルだけを調べ、変更する層と検証範囲を
> 示してください。実験の追加・再実行、非公開データの取得、公開・有料処理は行わず、
> 凍結済みのルール・ソース・結果を保存してください。

Codexが作業開始時に読む `AGENTS.md` は短い運用契約にし、長い背景説明はこのディレクトリへ
分けています。これは[公式のAGENTS.mdガイド](https://learn.chatgpt.com/docs/agent-configuration/agents-md)
に沿った構成です。リポジトリの中身を読んだだけで元タスクの会話・権限・実行状態まで
引き継がれるわけではありません。

## 最初に頼みやすい仕事

- 新候補の合法手と勝敗条件が説明と一致しているかを、コードと小さな局面でレビューする。
- 既存の反例・棄却理由を読み、同じ失敗を繰り返す提案を指摘する。
- ルールを変えずに、人間に分かりにくい説明・用語を改善する。
- 次の実験で区別したい仮説、必要な対照条件、停止条件を提案する（未承認の実行はしない）。

## PRに書くこと

目的／対象の層／変更ファイル／実行したテストと実際の終了結果／実行していない検証と理由／
ルール・予算・凍結物への影響。実験なら事前登録・入力hash・seed・上限・失敗時の扱いも書きます。
branchは `codex/` 接頭辞を基本とし、1つのPRで生成器・評価器・対戦AIを一緒に改善して
「どれが効いたか分からない」状態にしないでください。
